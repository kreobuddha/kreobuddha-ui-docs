A modal built on the native `<dialog>` element, for the one question that has to be answered before
anything else continues.

The element is the reason this component is small. The browser owns the top layer, the backdrop,
the focus trap, the inertness of the page behind it and `Escape` — none of which is reimplemented
here.

## Why the host owns `open`

The dialog never closes itself. Every route out of it — `Escape`, the close button, the backdrop —
calls `onClose` and stops there, so the decision to throw away what a reader typed always sits in
application code where it can be reconsidered.

`dismissOnBackdrop` exists for the same reason. It is on by default because that is what people
expect from a modal on the web, and it should be turned off for a dialog holding a half-filled
form: a stray click beside it otherwise discards the lot, and nothing warns first.

## Keyboard and screen readers

The focus trap, `Escape` and the inert background are the platform's. `title` is required because
it becomes the accessible name, and `description` is announced with it.

**One limitation, stated rather than patched:** on WebKit, closing does not return focus to the
element that opened the dialog. It is recorded on the [Accessibility](../../docs/accessibility/)
page rather than worked around here.
