One line of text, with the label, hint and error that make it usable wired up.

The component exists for the wiring rather than for the box. Associating a label, a hint and an
error message with an input means generating ids and threading `aria-describedby` and
`aria-invalid` — done by hand, per field, it is forgotten roughly as often as it is written. Here
it is not optional.

## There is no `invalid` prop

The error message is the invalid state. A field can be marked invalid without saying why — a red
border and nothing else — and that is a dead end for the reader: they know something is wrong and
have no way to find out what. Making the message the switch removes the option.

Two native attributes are replaced rather than shadowed. `size` here is the control scale that
matches `Button`, not the native width in characters; `prefix` is content inside the border, not
the RDFa attribute nobody reaches for.

## Keyboard and screen readers

The input is a real `<input>`; `ref` and every native attribute go to it, not to the wrapper. The
label is a real `<label>` bound by id. The hint and the error are announced with the field through
`aria-describedby`, and the error also sets `aria-invalid`, so a screen reader user is told the
field is wrong and told what is wrong in the same breath.
