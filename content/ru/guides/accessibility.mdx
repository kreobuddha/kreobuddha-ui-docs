Эта страница говорит, что проверено и чем, а что не проверено. Доступность — это не результат axe,
и библиотека, которая отчитывается только автоматической цифрой, отчитывается о самой лёгкой части.

## Подход

- **Сначала родная семантика.** Кнопка — это `<button>`, диалог — это `<dialog>`, чекбокс — это
  `<input type="checkbox">`. ARIA добавляется там, где у платформы нет элемента под нужный паттерн,
  а не вместо элемента, который есть.
- **Фокус виден и никогда не двигает раскладку.** Кольцо фокуса — акцентная граница в 2px,
  нарисованная внутри коробки, измеренная на 3:1 против поверхности за ней.
- **Контраст измеряется, а не оценивается на глаз.** Пары с текстом — 4,5:1 или лучше; границы
  контролов, статусные метки и кольцо фокуса — 3:1.
- **Движение уважает `prefers-reduced-motion`** — через токены длительности, а не покомпонентно.
- **Режим forced-colors сохраняет края оверлеев.** У панелей есть не только тень, но и граница,
  потому что forced colors не рисует тень вообще.

## Что проверено и чем

| Проверка                                                                                                | Чем                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ни одного нарушения axe ни в одной истории                                                              | `@storybook/addon-a11y` прогоняет axe по каждой истории в рамках тестового прогона, и нарушение роняет сборку                                              |
| Контраст каждой пары, которую компоненты выводят на экран, в обеих темах                                | `npm run check:contrast`, против целей WCAG 2.2                                                                                                            |
| Клавиатурная модель `Tabs` — стрелки, `Home`/`End`, одна остановка табуляции                            | функции `play` в его историях, исполняемые в настоящем Chromium раннером историй — не `check:browser`, который отвечает за кросс-движковую часть           |
| `Dialog` — фокус уходит внутрь панели, `Tab` из неё не выходит, страница позади инертна, `Escape` закрывает | `npm run check:browser`                                                                                                                                   |
| `Tooltip` — фокус открывает его, `Escape` закрывает, не сдвигая фокус                                   | `npm run check:browser`                                                                                                                                   |
| Оверлеи сохраняют границу под `forced-colors: active`                                                   | `npm run check:browser`, проверка идёт по вычисленному стилю, а не по скриншоту                                                                            |
| Поведение компонентов и их доступные имена                                                              | юнит-тесты на Testing Library, поиск по роли и имени                                                                                                       |

## Что не проверено

Три вещи, и все три названы, а не обойдены. Покомпонентная версия этой страницы — каждое утверждение
рядом с командой, которая его показывает, — лежит в репозитории в `docs/ACCESSIBILITY_CHECKLIST.md`.

**Проход со скринридером отложен.** Для `Dialog`, `Tabs` и `Tooltip` написан сценарий для VoiceOver,
и он не пройден. Нужны настоящие вспомогательные технологии в руках человека, и ни одна
автоматическая проверка в этом репозитории их не заменяет. **Пока сценарий не пройден, библиотека не
заявляет соответствия для скринридеров по этим трём компонентам.**

**В WebKit закрытие диалога не возвращает фокус кнопке, которая его открыла.** Фокус вместо этого
оказывается на `<body>` — и когда диалог закрыт по `Escape`, и когда кнопкой закрытия. Сам диалог
закрывается правильно, ловушка фокуса держится; теряется место читателя на странице. С восьмого
этапа набор поведенческих проверок гоняется в Chromium, Firefox и WebKit на каждом пул-реквесте,
и это отличие записано там как ожидаемое падение — так что набор сломается в тот день, когда движок
изменится. И это по-прежнему сборка WebKit из Playwright, а не Safari, который стоит у людей.

**В сборке WebKit под macOS `Tab` не доходит до кнопки закрытия тоста.** Safari держит кнопки вне
таб-порядка, пока читатель не включит «Press Tab to highlight each item on a webpage». Кнопка при
этом настоящая `<button>`, и `Enter` активирует её везде; отличие принадлежит клавиатурной модели
платформы.

Это заявленное ограничение, а не заплатка: поведение фокуса на оверлеях — дело браузера, и написанный
здесь путь восстановления был бы кодом, который должен быть правильным в каждом движке
и поддерживаться в согласии с двумя движками, которые и так всё делают верно, — ради компенсации
одного, который не делает. Решение пересматривается по двум поводам: если о проблеме сообщит
потребитель на практике или если она подтвердится в Safari, который стоит у людей.

## Что остаётся за хостом

Библиотека даёт доступные компоненты, а не доступное приложение. Порядок заголовков, структура
ориентиров, заголовки страниц, ссылки пропуска, управление фокусом при смене маршрута и смысл текста
внутри компонента остаются ответственностью хоста.
