## Контракт с DOM

Тёмная тема — это атрибут на любом предке, обычно на `<html>`:

```html
<html data-kreo-theme="dark"></html>
```

Светлая тема стоит по умолчанию и не требует атрибута вовсе. Атрибут читается селекторами CSS,
поэтому своя тема может быть у поддерева: `data-kreo-theme="dark"` на панели затемняет эту панель
и больше ничего.

## Библиотека не владеет состоянием темы

Она никогда не сохраняет выбор, не читает `prefers-color-scheme` и не пишет в DOM, чтобы сменить
тему. Это состояние принадлежит приложению: оно знает, где живут его настройки и когда их безопасно
записывать. Обычно хост делает что-то в таком духе:

```tsx
const applyTheme = (theme: 'light' | 'dark') => {
  const root = document.documentElement;

  if (theme === 'dark') {
    root.dataset['kreoTheme'] = 'dark';
  } else {
    delete root.dataset['kreoTheme'];
  }

  localStorage.setItem('theme', theme);
};
```

Переключение темы — работа хоста, и этот сайт — такой же хост, как любой другой: любой переключатель,
который он предлагает, — это приложение, выставляющее атрибут, а не возможность библиотеки.

## Переопределение

Кастомизация идёт через семантические токены, а не через классы компонентов. Каждое кастомное
свойство `--kreo-*` в опубликованных стилях — публичный API по SemVer; имена классов CSS Modules —
приватная деталь реализации и меняются без предупреждения.

```css
:root {
  --kreo-accent-500: #2f6f4f;
  --kreo-accent-600: #275e43;
}
```

Прежде чем что-то переопределять, стоит знать три соглашения.

**У статуса два цвета, а не один.** `--kreo-text-success` и его соседи — это читаемый текст на 4,5:1.
`--kreo-icon-success` и его соседи — более яркие метки для точек, иконок и границ, которым хватает
3:1. Схлопывание их в одно значение — ровно то, что превращает янтарный в коричневый.

**Тёмная тема живёт на меньшей насыщенности, чем светлая.** При равном контрасте цвет на тёмной
поверхности звучит громче, и первым это показывает зелёный. Палитра, перенесённая из светлой темы
один в один, будет выглядеть неоновой.

**Тонированной поверхности нужен свой цвет подписи.** `--kreo-surface-success-soft` и его соседи —
подложки, на которых стоят компоненты-сообщения; `--kreo-text-on-success-soft` и его соседи —
подписи, измеренные против этих подложек. Обычный текст статуса настроен против страницы и не
переживает переноса на собственную подложку в светлой теме.

`--kreo-shadow-overlay` зарезервирована за тем, что парит над страницей, — меню, диалоги, тултипы.
У оверлеев есть ещё и граница, потому что в режиме forced-colors тень не рисуется вовсе, и панель,
державшаяся на тени, потеряла бы край ровно там, где край нужнее всего.

## Каскад

**Стили идут без слоёв, и спор равных решает порядок загрузки.** Ни одно правило здесь не
лежит в `@layer`, поэтому ваше правило с той же специфичностью выигрывает просто потому, что
загружено после `@kreobuddha/ui/styles.css`. Это сделано намеренно и зафиксировано для линии `1.x` —
ADR-0019 — потому что введение слоёв позже молча поменяло бы, какие правила побеждают.
Поддерживаемый способ изменить внешний вид библиотеки — токены выше: они разрешаются там, где
используются, и от порядка не зависят вовсе.

## Держите пары контрастными

Если переопределяете палитру — измерьте результат. Команда `npm run check:contrast` в репозитории
проверяет каждую пару, которую компоненты выводят на экран, в обеих темах, против целей WCAG 2.2:
4,5:1 для текста, 3:1 для границ контролов, меток и кольца фокуса. Неизмеренное переопределение —
это непроверенное переопределение.
